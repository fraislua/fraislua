# バーティカルスライスとチーム開発の同期ロス対策

> 要約: 「キリの良さ」を待って各自のタスクを完成させてから合流する進め方は、チーム開発において同期ズレによる時間的ロスを生みやすい。共通のデッドライン（タイムボックス）で結合するアプローチについての考察。

## 「完成50% / 見せ方50%」という開発哲学

個人での制作を振り返ると、進捗が伸び悩む最大の要因は、作品全体を大きく作ろうとしてしまうことだった。そこで意識するようになったのが、「作品が動く・完成して50%。残りの50%はその説明・魅力・公開」という考え方である。

全体の完成を目指して頓挫するのを防ぐには、「最も手触りが気持ちいい1ステージ / 1戦闘サイクル」だけにスコープを絞り、早期に「完成度100%のコア体験」を固めるアプローチ、つまりバーティカルスライスが有効だと考えている。就活・公開のどちらの文脈でも、PV・GIFアニメ・README・企画意図の言語化といった「見せ方」は評価を分ける重要な要素であり、動くプロトタイプと魅力的な見せ方のセットを目標にするのが現実的だと感じている。

## バーティカルスライスという用語の理解

バーティカルスライス（Vertical Slice）とは、狭いスコープ（1ステージ/1戦闘など）を、最下層のシステムからUI・グラフィック・演出まで製品版クオリティで一気通貫に作り切る試作品を指す。

この考え方を個人開発からチーム開発に応用しようとしたとき、一つの課題が見えてきた。それが、方針転換や合流のタイミングにおける「同期ズレ」の問題である。

## 「キリが良い」の落とし穴

チームで方針転換を行う際、各自が「キリの良いところまでやってから移行する」という進め方を取ると、担当ごとの完了タイミングにズレが生じ、それが時間的なロスにつながる懸念がある。各自が担当部分を個別に完成させようとするほど、結合の段階で手戻りが発生しやすくなるためだ。

## 共通デッドライン（タイムボックス）で結合する

この問題への対策として有効だと考えているのが、「次のマイルストーン（例: 次週のミーティング）で『結合できる最小要素（仮モデル＋コアロジック＋基本UI）』を持ち寄る」という、共通の結合デッドライン（タイムボックス）を設定するアプローチである。それ以外の未完タスクは、その時点でいったん凍結する。

チームメンバーに対してこのアプローチを提案する際は、「全体を薄く広く作るより、1つ完成形がある方が就活のポートフォリオやチームのモチベーション向上に直結する」というメリットを併せて示すことで、納得感を得やすくなると考えている。
